## Deployment prerequisites

Don't run deployment or ingestion commands during the pause. Before later deployment, provision a PostgreSQL login for API health checks with CONNECT and no writer/table privileges. Set `XBRL_API_POSTGRES_DSN`. Provision the dedicated ClickHouse reader and its enforced query settings profile; set `XBRL_API_CLICKHOUSE_USERNAME` and `XBRL_API_CLICKHOUSE_PASSWORD`. Set `XBRL_API_KEY` and production mode for nonlocal use. Compose forwards only these API settings and the query budgets. It no longer loads the writer `.env` into the API.

Use the worker image with an explicit overridden command for migrations, initialization, and operator CLI actions. An explicit CLI command doesn't run the worker loop, but those commands remain prohibited during this pause. Don't follow older instructions that use the API service for privileged bootstrap after adopting the new environment split.

Keep one SEC-active process scheduled at a time. Stop or finish discovery before ingestion starts, and don't run catalog/discovery commands alongside a worker. Don't scale worker replicas. Independent external clients require a coordinated egress policy before concurrent use.

`XBRL_DISK_RESERVE_BYTES` defaults to 5368709120. This is a starting reserve, not a historical-backfill capacity estimate. Data-service defaults total 8 GiB before API/worker allocations; size the Docker VM and host accordingly. Apply resource configuration only in a separate authorized deployment. Route the new alerts through the operator's Alertmanager; application disk metrics don't replace remote-volume monitoring.
